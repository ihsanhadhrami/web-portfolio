# Portfolio v2

A production-ready personal portfolio for a modern web developer and digital
product engineer. Built with a dark-first, minimal aesthetic and a
data-driven architecture so content is trivial to maintain.

## Tech stack

- **React 19** + **TypeScript** (strict)
- **Vite 6** — fast dev server and optimized builds
- **Tailwind CSS v4** — design tokens via CSS variables, dark-first theme
- **shadcn/ui** conventions — `cn`, `class-variance-authority`, Radix `Slot`
- **Framer Motion** — subtle, reduced-motion-aware animations
- **React Router 7** — code-split routes
- **Lucide** — icons

## Getting started

```bash
npm install
npm run dev
```

Then open the printed local URL.

## Editing content

All content lives in `src/data/*` and `src/constants/site.ts`. The UI renders
entirely from these files — add or edit a project in `src/data/projects.ts`
and it appears everywhere automatically (home grid, projects page, detail
route, related work).

## Deployment (Cloudflare Workers)

Runs on Cloudflare Workers with static assets, built by
[`@cloudflare/vite-plugin`](https://developers.cloudflare.com/workers/vite-plugin/).
`wrangler.jsonc` is the single source of truth — Workers Builds needs no
dashboard settings beyond the build and deploy commands.

| Setting        | Value                     |
| -------------- | ------------------------- |
| Build command  | `npm run build`           |
| Deploy command | `npx wrangler deploy`      |
| Root directory | `/`                       |

`vite build` emits two things: the client bundle to `dist/client/`, and the
Worker to `dist/<name>/` alongside a generated `wrangler.json` that already
has `assets.directory` filled in. `wrangler deploy` picks that up
automatically — which is why `assets.directory` is **not** set by hand in
`wrangler.jsonc`.

Routing is split in `wrangler.jsonc`:

- `assets.not_found_handling: "single-page-application"` serves `index.html`
  with a 200 for any path that is not a real file, so React Router owns deep
  links and hard refreshes. This replaces the old `public/_redirects`
  catch-all, which Pages needed and Workers does not.
- `assets.run_worker_first: ["/api/*"]` sends API traffic to the Worker
  before the asset layer sees it. Without it, `/api/contact` would match the
  SPA fallback and return the app shell.

`public/_headers` still applies and is unchanged — Workers static assets
reads it natively (`✨ Parsed 5 valid header rules`). Note that these headers
apply to **asset** responses only, not to responses generated by Worker code.

Local development runs the same runtime as production: `npm run dev` and
`npm run preview` both execute the Worker under `workerd` via the Vite
plugin, so `/api/contact` works locally.

### Contact form

`POST /api/contact` is handled by the Worker in `worker/index.ts`, which
relays the message through [Resend](https://resend.com).

| Variable             | Where it lives                                  |
| -------------------- | ----------------------------------------------- |
| `RESEND_API_KEY`     | **Secret** — `npx wrangler secret put RESEND_API_KEY` |
| `CONTACT_TO_EMAIL`   | `vars` in `wrangler.jsonc`                      |
| `CONTACT_FROM_EMAIL` | `vars` in `wrangler.jsonc` (verified in Resend) |

Plain `vars` belong in `wrangler.jsonc` because `wrangler deploy` reconciles
them from the config file — a value set only in the dashboard would be
overwritten on the next deploy. Secrets are stored separately and are **not**
touched by a deploy, which is why the API key must never appear in the file.

For local runs, put all three in `.dev.vars` (gitignored) and use
`npm run dev`.

The form **never reports success unless the API confirms delivery** — it
requires a JSON `{ ok: true }` response, so a missing key or misconfigured
deploy surfaces a visible error rather than silently discarding enquiries.
The E2E suite stubs the endpoint at the network layer so success-path tests
never depend on a live Resend key or send real mail.

### SEO ownership

`index.html` owns the Open Graph and Twitter tags (social scrapers do not run
JavaScript, so they only ever see static HTML). The `<Seo>` component owns
`<title>`, the meta description, and the canonical link, so each route gets
its own. Declaring a tag in both places produces two conflicting copies —
`e2e/seo.spec.ts` asserts each appears exactly once. `sitemap.xml` is
generated at build time from `src/data/projects.ts`, so a new project can
never ship unindexed.
